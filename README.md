# DoloresUI

A design-system scaffold for **shadcn/ui (Base UI variant)** with Storybook, Tailwind v4, Geist, and Phosphor — wired with accessibility checks, interaction tests, and an MCP server for AI agents.

```
Next.js 16  ·  React 19  ·  Tailwind v4  ·  shadcn (Base UI / Nova)
Storybook 10  ·  Vitest 4 + Playwright  ·  axe-core  ·  MCP
Geist Sans / Mono  ·  @phosphor-icons/react
```

## What you get

- All 55 shadcn primitives installed under `components/ui/`, backed by [`@base-ui/react`](https://base-ui.com).
- A story file for every component (54 files, 215 passing tests) in `stories/`.
- **Editable Controls + Docs page** on every story via `tags: ['autodocs']` and `controls.expanded: true`.
- **Light / Dark toggle** in the Storybook toolbar (`withThemeByClassName` → `.dark` on `<html>`), matched by `next-themes` in the live app.
- **Accessibility** runs axe-core on every render via `@storybook/addon-a11y` in error mode. Known upstream-shadcn violations are surfaced as `a11y.test: 'todo'` rather than silenced.
- **Interaction tests** — story `play()` functions execute as Vitest specs in headless Chromium via `@storybook/addon-vitest`.
- **MCP server** at `http://localhost:6006/mcp` (`@storybook/addon-mcp`) so AI agents can list, preview, and scaffold stories.
- **Geist** typography via the `geist` npm package in the app, with a `next/font/google` fallback in Storybook (the local-font import isn't shimmed by `@storybook/nextjs-vite`).
- **Phosphor icons** everywhere. `components.json` `iconLibrary` is set to `phosphor`, so future `shadcn add` runs pull Phosphor too.

## Getting started

```bash
pnpm install
pnpm dev            # http://localhost:3000  – showcase landing page
pnpm storybook      # http://localhost:6006  – component catalog + MCP
pnpm test           # vitest + axe + Playwright
pnpm build          # next build (includes TypeScript checker)
pnpm build-storybook
```

Requirements: Node ≥ 20, pnpm ≥ 10. Playwright's Chromium is installed automatically by the Storybook init; if you need to re-install it, run `pnpm dlx playwright install chromium`.

## Adding components

```bash
pnpm dlx shadcn@latest add <component-name>
```

The Base UI variant is selected automatically (it's pinned in `components.json` via `style: "base-nova"`). After adding a component, write its story in `stories/<PascalCase>.stories.tsx` following the pattern in `stories/Button.stories.tsx`:

- `tags: ['autodocs']` for the Docs page
- `argTypes` to expose Controls for variant/size props
- At least one `Interaction` story with a `play()` function that asserts behavior via `storybook/test`
- Phosphor icons from `@phosphor-icons/react` (never `lucide-react`)

## Theming

CSS variables in `app/globals.css` are the single source of truth. The `.dark` block overrides them. Both the app (`next-themes`) and Storybook (`@storybook/addon-themes`) toggle the `dark` class on `<html>`, so styles stay in sync between contexts.

Tailwind utilities like `bg-background`, `text-foreground`, `border-border`, and `text-muted-foreground` map to the appropriate token via `@theme inline`. Never hardcode hex/oklch values — extend the token block instead.

## MCP server

When Storybook is running, it serves a Model Context Protocol endpoint at `http://localhost:6006/mcp`. To register it with your local agent configuration:

```bash
pnpm dlx mcp-add --type http --url "http://localhost:6006/mcp" --scope project --name doloresui-sb-mcp
```

The MCP server exposes tools for listing stories, fetching component documentation, generating preview URLs, and scaffolding new stories. See `AGENTS.md` for the expected agent workflow.

## Known a11y todos

Several stories are marked `a11y.test: 'todo'` because they surface real axe violations upstream of this repo:

- shadcn's `destructive` variants (Button, Badge, AlertDialog) — 4:1 contrast vs WCAG AA 4.5:1
- Base UI Slider, ToggleGroup, Menubar, NavigationMenu, Combobox — upstream aria patterns
- Several stories using `text-muted-foreground` on muted backgrounds (AspectRatio, Avatar, Item, Kbd, Field)
- Vertical Resizable — `react-resizable-panels` applies `overflow: auto` without focusability

These are visible in the Storybook a11y panel; the test runner records them as `todo` rather than `fail`. Fixing them properly means either tweaking the relevant CSS token in `globals.css` or filing upstream issues.
